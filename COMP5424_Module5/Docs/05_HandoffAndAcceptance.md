# 第五模块交接与十月六日验收

本模块已提供文件和内容，验收需要团队在真实工程中完成。下面的“待测”不得因文件格式检查通过而改为“已完成”。

| 接收负责人 | 交接内容 | 需要对方实际完成的工作 |
|---|---|---|
| 场景负责人 | Kenney 桌椅、门框、可选楼梯/纸箱；原创电梯立面；标识 PNG、面板 OBJ | 检查现有 OBJ，选择必要素材；确认比例、朝向、材质、碰撞和标识位置，保持路线可走；左右箭头与实际方向一致。 |
| UI 负责人 | 七节点文案、JSON、逐条录音稿；电梯反馈标识 | 按卡片显示；设置选择电梯后触发及关闭；控制重复弹窗；不要向参与者展示编辑占位符。 |
| 移动负责人 | 按键说明的三个待确认位置；楼梯节点 | 提供实际移动、选择、暂停退出操作；验证楼梯上行/下行或 teleport 不会绕过必要节点、卡住或强迫真实移动。 |
| 设备与测试负责人 | 四个默认 WAV、三个备选 OGG、纹理与英文 UI | 在最终目标运行方式及 Quest 3 头显上验证解码、音量、清晰度、静音可理解与文字可读性；测场景性能。 |
| 仓库负责人 | Assets/Module5、许可文件、来源表、文档 | 用团队约定路径合并；Unity 首次导入后保留生成的 .meta；按团队规则管理二进制文件；不把原始第三方下载 ZIP 或私有研究缓存导入 Assets。 |

## 建议执行顺序

1. 十月一日至二日：团队确认现有建筑包含哪些物件、楼层/终点定义及是否保留旧路线变化事件；确认输入绑定。
2. 十月二日至四日：场景与 UI 负责人导入所需模型和 PNG，把 C01/C04/C06 接到旅程事件；声音负责人选定一套短音效。
3. 十月四日至五日：完整从教室到终点跑一遍，再跑“选择电梯后继续”的分支和静音版本；记录问题并修正。
4. 十月六日前：设备负责人提供目标构建与头显验证记录，用户整理自己的素材选择、来源核对、文案修改和整合贡献。此顺序是建议内部安排，不是课程新增截止。

## 内容发布前必须完成

- [ ] 移动、选择、暂停退出三个占位符已替换为真实操作，且构建中确实可用。
- [ ] Level 1 终点的位置已由团队确认；未把它未经验证地称为 ground floor、建筑外集合点或现实安全保证。
- [ ] 电梯解释出现在确认选择之后；接近电梯不会自动给出答案；重复点击不叠加面板/声音。
- [ ] 每一处箭头都对应实际门/楼梯方向；墙面标识在 Quest 3 内清晰可读。
- [ ] 纸箱和封路情节只有在团队确认需求后启用；旧 Phase 1 的路线恢复要求已有明确处理记录。
- [ ] 静音完整运行时，练习仍可理解和完成；旁白（如录制）与字幕一致。
- [ ] 起点、楼梯、终点以及电梯分支均实际测试；没有穿模、卡住、错误比例或跳过必要节点。
- [ ] 音效在 Quest 3 试听，音量与舒适度记录已保存；停止/暂停行为明确。
- [ ] Kenney 许可和来源记录随提交保留，实际素材由本人的分支/PR或团队确认记录可追踪。
